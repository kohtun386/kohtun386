01 Nexus Factory ERP

owner · admin · supervisor · editor · viewer

Governed, multi-tenant workforce-intelligence SaaS for garment factories — a factory ERP where the database itself enforces the business rules.

  • Tenant context

    Every policy gates on factory_id = current_factory_id(), resolved from active membership — and factory_id itself is immutable across ~20 tables.

  • Write: RPC-only

    production_logs carries only a SELECT policy — clients cannot INSERT, UPDATE, or DELETE. All writes flow through approve_production_log / log_production_atomic, which open a write path via a session flag no client session can set.

  • Audit: append-only

    audit_logs raises on UPDATE and DELETE. The trail cannot be rewritten, and the approval flow writes its own audit entry.

  • State: locked

    Approved logs are locked — only payment_status may change. Payroll is a real state machine: DRAFT → CALCULATED → FINALIZED → PAID, with invalid transitions rejected by trigger.

  • Atomic allocation

    On approval, material consumption is computed from a required_materials snapshot and written atomically with stock movements and trace rows — idempotent on retry.

  • Onboard: invite-only

    Invitation RPCs plus a provision-tenant Deno edge function create factory and owner; tenant isolation is in place from day one.

  • CI: governed writes

    A script greps the entire frontend for any forbidden direct table write and fails CI — a belt-and-suspenders layer on top of RLS.

Found in review

  • E2E tests exist but are not wired into CI.
  • deploy/SECURITY_NOTES.md claims an npm audit step that CI does not actually run.
  • The README quotes a “canonical UPDATE policy” from an archived migration — the live baseline is stricter, with no client UPDATE path at all.

02 POS-system

platform_admin · admin · manager · cashier

Multi-tenant SaaS POS for Myanmar coffee & tea shops — a 12-commit starter rebuilt into a tiered, RLS-hardened platform. 404 commits ahead of upstream.

  • Atomic checkout

    checkout_complete recomputes the total server-side — a tampered client amount is ignored — then reserves invoice numbers, deducts stock, and updates customer stats in one transaction.

  • 9 payment methods

    KBZpay, WavePay, AYAPay, CBPay, MPU — plus split payments and credit sales, built for Myanmar payment reality.

  • Tiered SaaS

    Free / Growth / Pro enforced server-side: a 50-product limit with row-lock race protection and daily-order limits with SELECT … FOR UPDATE.

  • Role-aware RLS

    platform_admin never appears in a policy — it operates only through service-role Edge Functions. Privileged RPCs are REVOKE EXECUTE FROM PUBLIC; one Greptile-audited HIGH-severity vector was closed exactly this way.

  • Audit: implicit deny

    audit_logs has zero RLS policies — implicit deny for clients; only Edge Functions write, capturing IP from X-Forwarded-For.

  • Data: minimized

    Card numbers are stripped from JSONB in production data, and a CORS wildcard was replaced with an explicit allowlist.

  • Tested

    33 pgTAP RLS tests · 11 Vitest suites · 7 Playwright journeys. i18n parity and schema-drift gates run in CI and on pre-commit.
